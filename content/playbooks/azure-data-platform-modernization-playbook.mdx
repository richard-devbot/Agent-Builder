# Azure Data Platform Modernization Playbook

A 9-phase playbook for building or modernizing a cloud data platform on Azure: ADF / Fabric pipelines, PySpark transformations, Synapse / Fabric warehouse, BI consumption, and data governance. Click through the phases — each one points you at the right templates, skills, and MCP configs to use in your IDE, with a clear definition-of-done before you move on.

## When to use this playbook

- You're building or modernizing a cloud data platform on Azure
- Sources include a mix of SaaS, on-prem, and cloud databases
- The target platform is Fabric, Synapse, or some hybrid
- The work spans multiple business domains and consumers (BI / ML / apps)

## When NOT to use this playbook

- **You're retiring a legacy ETL tool specifically.** Use the [Legacy ETL to Azure Modernization Playbook](/playbook/legacy-etl-to-azure-modernization-playbook) instead — it focuses on parity and cutover.
- **You're building a small one-off pipeline.** This playbook is platform-scale; for a single pipeline, just use the templates directly.
- **Your stack isn't Azure.** The patterns generalize but the specifics (ADF, Fabric, Synapse, ADLS, Purview) don't.

## Independent of the other playbooks

This playbook is for **building / modernizing the Azure data platform**. For retiring a specific legacy ETL tool, see [Legacy ETL to Azure Modernization](/playbook/legacy-etl-to-azure-modernization-playbook). For application migrations, see [ASP.NET Modernization](/playbook/aspnet-to-angular-dotnet-modernization-playbook), [VB.NET WinForms Migration](/playbook/vbnet-winforms-to-spa-migration-playbook), [COBOL Modernization](/playbook/cobol-modernization-playbook), or [RPG / IBM i Modernization](/playbook/rpg-modernization-playbook). For pure DB engine moves, see [Database Migration](/playbook/database-migration-playbook).
