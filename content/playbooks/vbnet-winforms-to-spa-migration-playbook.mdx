# VB.NET WinForms to SPA + .NET API Migration Playbook

A 10-phase playbook for moving a legacy VB.NET WinForms desktop application onto the web — SPA frontend, .NET API backend, cloud-hosted, multi-user concurrent. This is the hardest migration scenario because it's not just tech translation: it's an architectural reshape from single-user desktop to multi-user web.

## When to use this playbook

- You have a VB.NET WinForms app (4.x or earlier) that needs to become a web app
- The app must keep running while you migrate
- Users will continue to need the app (you're not deprecating, you're modernizing)
- Timeline is multi-quarter (anything &lt;6 months should question scope)

## Why this is harder than web-to-web

Web-to-web migrations (e.g., ASP.NET → Angular) translate UI patterns one-to-one most of the time. Desktop-to-web doesn't. The reasons:

- **Concurrency model** — desktop is single-user-at-a-time; web is concurrent. Every assumption about "I'm the only one editing this" has to be revisited.
- **Resource access** — desktop has direct file/registry/printer/COM access; web doesn't.
- **State** — desktop holds tons of state in memory across long-running sessions; web is stateless or session-scoped.
- **Latency** — desktop talks to local DB at sub-millisecond latency; web talks to cloud DB over the network.
- **UX patterns** — modals, dense grids, keyboard-driven workflows have different web equivalents.

Phase 2 (architectural reshape) is where most desktop-to-web migrations fail. Get it right; the rest follows.

## Independent of the other playbooks

This playbook is for **modernizing existing desktop apps**. If you're starting from scratch, use the [Custom Web App Playbook](/playbook/custom-web-app). If you're modernizing a web app, use the [ASP.NET Modernization Playbook](/playbook/aspnet-to-angular-dotnet-modernization-playbook).
