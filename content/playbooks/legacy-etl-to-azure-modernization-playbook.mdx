# Legacy ETL to Azure Modernization Playbook

Migrate legacy ETL tooling (Informatica PowerCenter, SQL Server Integration Services, DataStage, Pentaho, etc.) to a modern Azure-based stack — ADF, Fabric Data Pipelines, and PySpark for transformations. **The hard case** — you have hundreds of existing mappings producing critical reports, and you need to replace them without breaking anything.

If you're standing up a new data platform from scratch (no legacy to retire), use the [Azure Data Platform Modernization Playbook](/playbook/azure-data-platform-modernization-playbook) instead.

## When to use this playbook

- You have a legacy ETL tool you're retiring (Informatica, SSIS, DataStage, Pentaho, etc.)
- The pipelines are running in production and feeding critical reports
- You need behavior parity (output of new pipelines = output of old, for trusted consumers)
- The new platform is Azure-based (ADF, Fabric, Synapse, PySpark)

## When NOT to use this playbook

- **Greenfield platform with no legacy.** Use the [Azure Data Platform Modernization Playbook](/playbook/azure-data-platform-modernization-playbook).
- **Just upgrading versions of the same tool.** That's a vendor upgrade, not modernization.
- **Replacing one legacy ETL with another legacy ETL.** Don't do this; it's putting lipstick on a pig.

## Why ETL migration is different from app migration

| Concern | App migration | ETL migration |
|---|---|---|
| What's migrated | User-facing features | Data pipelines (invisible) |
| Failure mode | UI breaks, user complains | Wrong data ships, decisions made on it, found weeks later |
| Parity bar | Behavior matches in user actions | Output matches across data, including quirks |
| Rollback | Flip the flag back | Reverse-flow the data |
| Cutover style | Per slice, gradual | Per pipeline, parallel run mandatory |

ETL parity is harder than app parity. The new pipelines must produce **the same numbers** — or trust evaporates and the project stalls.

## Independent of the other playbooks

This playbook is for **legacy ETL → Azure**. For greenfield Azure data platforms, see [Azure Data Platform Modernization](/playbook/azure-data-platform-modernization-playbook). For application migrations, see [ASP.NET Modernization](/playbook/aspnet-to-angular-dotnet-modernization-playbook), [VB.NET WinForms Migration](/playbook/vbnet-winforms-to-spa-migration-playbook), [COBOL Modernization](/playbook/cobol-modernization-playbook), or [RPG / IBM i Modernization](/playbook/rpg-modernization-playbook).
